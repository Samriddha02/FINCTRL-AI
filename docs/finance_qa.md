# Phase 9 — Finance Q&A / Grounded Finance Assistant

## Overview
Phase 9 implements a fact-first, grounded natural-language Finance Q&A engine. Every answer generated by the system is strictly derived from authoritative operational database records using read-only tools and deterministic Decimal calculations.

```
User Natural Language Question
              │
              ▼
    Deterministic Router
  ├── Question Classification (PAYMENT, INVOICE, TAX, RECONCILIATION, AGGREGATION, etc.)
  ├── Entity / ID Extraction (PAY-00001, INV-00001, CASE-00001, etc.)
  └── Security & Scope Filter (Blocks SQLi, Path Traversal, Unsupported / Chatbot queries)
              │
              ▼
   Read-Only Data Retriever
  ├── Read-Only Tools (get_payment_details, get_invoice_details, etc.)
  └── Deterministic Aggregations (SUM, COUNT via Decimal)
              │
              ▼
  Authoritative Fact Model & Calculations
  ├── QAFactRecords (key, value, source, entity_id)
  └── QACalculations (formula, value, Decimal precision)
              │
              ▼
     LLM Explanation Engine
  (Formats grounded facts concise explanation via LLMProvider / MockLLMProvider)
              │
              ▼
    Deterministic Answer Validator
  (Validates that IDs and numeric claims match authoritative facts)
              │
              ▼
      Cited Answer & Audit Event
  ├── Citations: ["Payment PAY-00001", "Invoice INV-00001"]
  └── Audit Log: FINANCE_QA_ANSWERED event
```

## 1. Supported Question Categories
* **Payment Status**: e.g., *"Was PAY-00001 captured?"*, *"What happened to payment PAY-00001?"*
* **Order Status**: e.g., *"What is the status of ORD-00001?"*, *"Which customer placed ORD-00001?"*
* **Refunds**: e.g., *"How much was refunded for PAY-00001?"*
* **Settlements**: e.g., *"Was PAY-00001 settled?"*, *"What settlement is associated with PAY-00001?"*
* **Bank Transactions**: e.g., *"Show bank transactions related to SETTL-00001."*
* **Invoices**: e.g., *"What is the invoice amount for ORD-00001?"*, *"How much tax was charged on INV-00001?"*
* **Tax Records**: e.g., *"What tax was recorded for INV-00001?"*, *"Compare invoice tax with tax ledger tax."*
* **Reconciliation**: e.g., *"Why is CASE-00001 mismatched?"*, *"What is the reconciliation status of CASE-00001?"*
* **Aggregations**: e.g., *"How many total payments are there?"*, *"What is the total payment amount?"*, *"How many cases require investigation?"*
* **Cross-Entity Queries**: e.g., *"Show payment, settlement, and bank transaction for PAY-00001."*

## 2. Out-of-Scope & Ambiguous Queries
* **Out-of-Scope Requests**: Personal advice, general conversation, investment advice, or database write requests are gracefully rejected with `status: "UNSUPPORTED"`.
* **Ambiguous Requests**: Specific detail requests lacking a concrete record ID (e.g. *"What happened with the payment?"*) return `status: "NEEDS_CLARIFICATION"` with a prompt requesting a specific identifier.
* **Missing Records**: If a valid ID is requested but does not exist in the database (e.g., `PAY-99999`), the system returns `status: "NO_DATA"` without hallucinating values.

## 3. Fact-First & Deterministic Calculations
* All financial values and sums use Python `Decimal` arithmetic.
* The LLM is never allowed to perform mental math or invent numeric values.
* Fact records (`QAFactRecord`) and calculation records (`QACalculation`) are maintained separately from natural language explanations.

## 4. Hallucination & Validation Layer
* `validate_qa_answer` verifies that every numeric claim and entity ID in the answer corresponds to retrieved `facts` or `calculations`.
* If validation fails, `status: "VALIDATION_FAILED"` is logged, and a deterministic facts-first answer fallback is returned.

## 5. Security & Ground-Truth Isolation
* **Security**: Entity IDs are parsed and validated using `validate_id` (blocking SQL injection and path traversal).
* **Prompt Injection Defense**: Database field values are sanitized as untrusted data before prompt construction.
* **Ground-Truth Isolation**: Q&A modules do not import or access `ground_truth.csv`.

## 6. API & Audit Integration
* `POST /api/finance/qa`: Accepts `{"question": "..."}` and returns structured `FinanceQAResult`.
* `GET /api/finance/qa/{query_id}`: Retrieves previous Q&A query result.
* Every query emits immutable audit events (`FINANCE_QA_REQUESTED`, `FINANCE_QA_ANSWERED`, `FINANCE_QA_UNSUPPORTED`, `FINANCE_QA_CLARIFICATION_REQUIRED`, `FINANCE_QA_NO_DATA`).
